# Day 2 Lab – Reasoning and Acting

## 1. Scenario

### College Event Planning Assistant

The selected scenario is planning a college event for 120 participants.

Given information:

- Number of participants: 120
- Team size: 4 participants
- Material cost per team: Rs.150
- Budget limit: Rs.5,000

The task is to calculate the number of teams, estimate the total material cost, check whether the plan is within budget, and select a suitable venue.

Venue information is obtained through the `get_event_information()` tool.

The expected calculation is:

- Number of teams = 120 / 4 = 30 teams
- Material cost = 30 × Rs.150 = Rs.4,500
- Budget status = Rs.4,500 is within the Rs.5,000 limit
- Seminar Hall capacity = 150, so it can accommodate 120 participants.

---

## 2. Direct Prompting

Direct prompting produces an answer directly from the given information.

In this implementation, the direct prompting approach does not call any external tool and does not display intermediate reasoning steps.

### Result

- Number of teams: 30
- Total material budget: Rs.4,500
- Budget status: Within the budget
- Suitable venue: Seminar Hall

### What it can answer

Direct prompting can answer questions when the required information is already available in the prompt or known context.

### What it cannot answer

It cannot independently obtain new external information because no tool is used in this approach.

### Advantages

- Fast
- Simple
- Low computational overhead
- Easy to implement

### Limitation

The reasoning process is not shown, and the approach does not have tool access in this implementation.

---

## 3. Chain-of-Thought

Chain-of-Thought reasoning breaks the problem into multiple reasoning steps before producing the final answer.

The implementation demonstrated the following reasoning sequence:

1. Identify the total number of participants: 120.
2. Divide 120 participants by 4 members per team.
3. Calculate 30 teams.
4. Calculate the material cost: 30 × Rs.150 = Rs.4,500.
5. Compare Rs.4,500 with the Rs.5,000 budget.
6. Determine that the plan is within the budget.
7. Identify that a venue with at least 120 capacity is required.

### Result

- Number of teams: 30
- Total material budget: Rs.4,500
- Budget status: Within the budget
- Required venue capacity: At least 120 participants

### What it can answer

CoT is useful for multi-step reasoning and calculations when the required information is already available.

### What it cannot answer

Without a tool, it cannot retrieve new external information such as live venue availability or current prices.

### Advantages

- Makes the reasoning process easier to follow
- Useful for multi-step calculations
- Helps break complex problems into smaller steps

### Limitation

The approach used in this lab is a local simulation and does not represent hidden reasoning generated by a live LLM.

---

## 4. ReAct

ReAct combines reasoning with actions and observations.

The implementation follows this sequence:

### Thought

The agent identifies that it needs to calculate the teams and material budget and also needs venue information.

### Action

The agent calls:

`get_event_information()`

### Observation

The tool returns:

- Available venues: Seminar Hall and Auditorium
- Seminar Hall capacity: 150
- Auditorium capacity: 500
- Material cost per team: Rs.150

### Thought

The agent calculates:

- 120 / 4 = 30 teams
- 30 × Rs.150 = Rs.4,500

It then checks the venue capacity.

### Final Answer

- Number of teams: 30
- Total material budget: Rs.4,500
- Budget status: Within the budget
- Selected venue: Seminar Hall

### What it can answer

ReAct can combine reasoning with information obtained through a tool.

### Tool usage

The `get_event_information()` function acts as the external-information tool in this lab.

### Advantages

- Can use tool information
- Suitable for tasks requiring external information
- Combines reasoning, action, and observation
- Useful for multi-step agent workflows

### Limitation

The tool used in this lab is a local simulated external-information tool. It is not connected to a live web service or external API.

## 5. Comparison of Approaches

| Factor | Direct Prompting | Chain-of-Thought | ReAct |
|---|---|---|---|
| Reasoning depth | Low | High | High |
| Tool usage | No | No | Yes |
| Multi-step reliability | Basic | Better for calculations | Better when external information is required |
| Transparency | Final answer only | Reasoning steps shown in this lab | Thought, Action and Observation shown |
| Speed / Cost | Fastest | More processing | More processing due to tool calls |
| Consistency | Usually deterministic in this implementation | Can vary in a stochastic LLM setting | Can vary depending on reasoning and tool results |
| External information | Not available | Not available | Available through tools |
| Best use case | Simple direct questions | Multi-step reasoning | Reasoning + external information |

## 6. Self-Consistency Experiment

Self-consistency was demonstrated using a reasoning question:

**Question:** How many teams are required for 120 participants when each team contains 4 participants?

The experiment used a simulated non-zero temperature of 0.7 and five runs.

### Results at Temperature 0.7

| Run | Answer |
|---|---|
| Run 1 | 30 teams |
| Run 2 | 30 teams |
| Run 3 | 30 teams |
| Run 4 | 30 teams |
| Run 5 | 31 teams |

The majority answer was:

**30 teams**

The majority answer is correct because:

120 / 4 = 30 teams

### Results at Temperature 0

| Run | Answer |
|---|---|
| Run 1 | 30 teams |
| Run 2 | 30 teams |
| Run 3 | 30 teams |
| Run 4 | 30 teams |
| Run 5 | 30 teams |

At temperature 0, the simulated output remained consistent across all five runs.

### Observation

The non-zero temperature experiment demonstrated variation between generated candidate answers, while the temperature 0 experiment produced the same answer each time.

Self-consistency uses multiple candidate reasoning results and selects the majority answer. In this experiment, the majority answer was the correct answer: 30 teams.

### Important Implementation Note

This lab uses a local deterministic/stochastic simulation rather than a live LLM API. Therefore, the temperature experiment demonstrates the concept of self-consistency rather than measuring the actual sampling behaviour of a specific language model.

## 7. Suitability Analysis

### Direct Prompting

Direct prompting is suitable when the question is simple and all required information is already available.

For example, calculating a simple value from known inputs can be handled directly.

### Chain-of-Thought

Chain-of-Thought is suitable when a problem requires multiple reasoning steps.

For this event-planning problem, it helps break the calculation into participant count, team calculation, cost calculation, and budget comparison.

### ReAct

ReAct is suitable when the task requires both reasoning and external information.

In this scenario, venue capacity information is obtained through a tool before selecting a venue.

Therefore, ReAct provides the workflow needed when a question cannot be completely answered from the initial information alone.

### Self-Consistency

Self-consistency is useful when multiple reasoning attempts may produce different answers. A majority vote can help select a consistent answer from multiple candidate outputs.

---

## 8. Limitations of This Lab

The main limitation is that the experiment was implemented without a live external LLM API.

The CoT, ReAct, and self-consistency behaviours were therefore simulated locally to demonstrate the concepts required by the assignment.

The venue information tool is also a local simulated tool rather than a live web search, database, or API.

Because of this, the results should be interpreted as a conceptual demonstration of the three reasoning approaches and self-consistency rather than as a benchmark of a specific language model.

---

## 9. Conclusion

This experiment demonstrated three different approaches to solving an event-planning problem.

Direct prompting provides a quick final answer without intermediate reasoning or tool usage.

Chain-of-Thought demonstrates how a multi-step calculation can be broken into smaller reasoning steps.

ReAct extends the process by combining reasoning with an action and observation from a tool. This makes it useful when external information is required.

The self-consistency experiment demonstrated that multiple candidate answers can be compared using majority voting, while temperature 0 produced a consistent answer in the local simulation.

Overall, the experiment shows that the choice of approach depends on the requirements of the task: direct prompting for simple questions, Chain-of-Thought for multi-step reasoning, and ReAct when reasoning must be combined with tool-based information.
